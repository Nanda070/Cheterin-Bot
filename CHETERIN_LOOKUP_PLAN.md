# Cheterin Lookup — продуктовый план

Статус: план, **решения зафиксированы**. Реализации в этом документе нет.  
Публичный адрес: `https://cheterin.online/lookup` (в проде HTTPS; путь `/lookup`).  
Этот документ **не** является спецификацией кода и **не** предлагает править VALORANT, cogs бота или текущий дашборд, пока не начнётся отдельная задача реализации.

Референс по **компоновке экранов** (не по цвету и не по текстам): [dclookup.id](https://www.dclookup.id/) — hero-поиск, карточка профиля, двухколоночные детали, теги, ряды ассетов, сетка бейджей, калькулятор прав + live preview. Референс **не** является источником юридических текстов, копирайта, бренда, палитры, рекламы или API-контракта.

Визуальный язык экосистемы — **один**, не mix: **угольный + красно-тёмный** (см. §2, §6.2). Не blurple Discord, не чёрно-бело-синие ID-карточки референса, не отдельная «тема Lookup» рядом с «темой about».

---

## 1. Цель

Сделать публичный Lookup — отдельный продукт экосистемы Cheterin: поиск открытых Discord-данных по ID / инвайту и набор утилит (права, ассеты, бейджи, snowflake, DSA, каталог плагинов).

Lookup должен:

- жить по адресу `cheterin.online/lookup` и не требовать входа в панель;
- **не зависеть от процесса Discord-бота Cheterin** (сейчас панель стартует из `main.py` вместе с ботом — падение/рестарт бота не должен гасить Lookup);
- использовать **отдельное Discord Application** и отдельный bot token, не токен Cheterin;
- выглядеть как инструмент (карточки, hero-поиск, tools) с **той же** угольно-красной системой, что публичный chrome Cheterin — не как ещё одна страница дашборда и не как перекрашенный dclookup;
- **сильно** выигрывать у типичного lookup-сайта визуально **и** текстами: тексты со смыслом, не lorem, не сырой маркетинг;
- говорить на тех же языках, что и остальной Cheterin: **RU / EN**, по умолчанию русский, ключ языка **`chetbot_ui_lang`**;
- быть честным в том, что Discord API реально отдаёт, и не обещать «полный профиль», приватные гильдии, Group DM или ленту «недавних поисков».

`/about` остаётся **витриной бота Cheterin** в существующем `dashboard/frontend` (модули, «добавить бота», docs) — не Lookup. Тот же UI-kit (уголь + тёмно-красный), **без** поля поиска и **без** lookup-hero. Единственный мост на Lookup с about — кнопка **«Lookup»** → `/lookup`. Поле поиска живёт **только на `/lookup`**. Страница `/lookup/about` — короткий about **продукта Lookup** (текст, без дубля гигантского hero).

Это не замена панели, не OSINT-сервис и не клон dclookup.id под другим доменом. Это публичный инструмент Cheterin Group с **одной** правовой рамкой (Terms / Privacy / Cookies / Disclaimer) на оба продукта.

## 2. Locked decisions

Зафиксировано. Не переоткрывать без явного решения.

### 2.1. Продукт и границы

1. **Server lookup только по invite-коду.** Vanity (`discord.gg/имя`) — это тоже код. Голый Guild ID **не** принимается: бот Lookup не обязан состоять на сервере, а `GET /guilds/{id}` без членства недоступен. Пользователь вставляет код или полную ссылку — UI нормализует до кода.
2. **i18n как у остального Cheterin: RU и EN.** Словари, переключатель языка, `lang` на `<html>`. Дефолт — русский. Не третий язык в v1. Ключ: **`chetbot_ui_lang`** (общий с about/панелью/docs).
3. **Дополнительно к lookup сущностей: только DSA и Snowflake.** Group DM lookup **нет** (ни инвайт `discord.gg/xxxxx` группового чата, ни UI-режим).
4. **Plugins: каталог + внешние ссылки.** Наполнение — **список от оператора** на момент создания каталога; реалилизатор вносит в манифест. Модерация: **только оператор**. Публичных немодерируемых сабмишенов в v1 нет. Каркас страницы не блокирует релиз, если список ещё пуст (честный empty state).
5. **`/about` без поиска, остаётся в `dashboard/frontend`.** Витрина бота; restyle под кит §6.2; в hero (и вообще на странице) **нет** поля поиска и **нет** lookup-hero. Только кнопка/ссылка **«Lookup»** → `/lookup`. Lookup SPA владеет **`/lookup/*`**.
6. **`/lookup/about` есть в v1.** Короткий about **сервиса Lookup** (что это, независимость от бота, disclaimer). **Не** копия `/about` бота. **Без** гигантского hero-поиска (поиск уже на `/lookup`). Опциональная маленькая строка поиска на about Lookup не нужна, если чище без неё.
7. **Legal — один набор страниц на оба продукта**, не два комплекта. Оператор: **Cheterin Group Ø / Nandak070**. Канон URL: корневые `https://cheterin.online/terms`, `/privacy`, `/cookies`, `/disclaimer` (футер Lookup и about указывают туда). Тексты — Cheterin-style, лучше шаблона; Cookies **одна** страница на панель и Lookup. Язык Lookup — через cookie/`localStorage` **`chetbot_ui_lang`**, не «без cookie любой ценой».
8. **Нет публичной ленты недавних поисков.** Ни «recent», ни глобальной стены запросов, ни чужих ID на главной. Антиабьюз-логи **не** являются фидом.
9. **Отдельный Discord Application token.** Трафик Lookup не идёт через токен бота Cheterin. При злоупотреблении Lookup Cheterin не должен потерять приложение.
10. **Визуал и копирайт — сильно лучше, это принцип продукта, не полировка в конце.** Каждый экран выглядит и читается как законченный продукт Cheterin. **Запрещено:** lorem, placeholder-рыба, сырой маркетинг, калька dclookup, пустые «Check Demo». RU и EN равноценны. Несданный копирайт = несданный экран. Макеты — **паритет раскладки** со скриншотами референса (§6.4).
11. **Одна палитра: угольный + красно-тёмный — везде.** Одни токены на `/about`, `/lookup`, `/lookup/about`, tools, legal, публичный chrome дашборда. Залогиненная панель **не** маскируется под lookup-карточки, но **цвета те же**. В v1 канон токенов — **дубль CSS-переменных** в `lookup/` и публичном CSS дашборда, пока нет `packages/ui`.
12. **Имя в шапке: «Cheterin»**, не «Cheterin Lookup». Контекст Lookup даёт URL и страница, не второе имя бренда.
13. **Папки: вариант A.** `lookup/` + `lookup-api/` на корне репозитория. Не внутри `dashboard/frontend`.
14. **API: тот же хост, префикс `/api/lookup/...`.** Без lookup-поддомена (меньше CORS).
15. **Bot lookup v1 = полная карточка** (User object + публичные application-поля: about, scopes, permissions, intents). Если endpoint нестабилен — retry и кэш; деградация до «только user» **только** если Discord ничего не отдал. Не закладывать «user-only» как целевой v1.
16. **Калькулятор прав — полный:** generic invite URL **и** поле Client ID **и** пресеты ID приложения Lookup и бота Cheterin из **конфига** (не секреты в исходниках).
17. **Скачивание ассетов — оба пути:** основной = прямые ссылки Discord CDN; same-origin прокси — fallback при CORS / имени файла при download.
18. **Мониторинг не на hero.** Внутренний health Lookup API — да. Фейковые статус-дашборды как у референса — нет. Дискретный футер/статус — не v1 (можно позже).
19. **Рейт-лимит UX:** до порога — **429** с retry (Retry-After). После **30 запросов / минуту / IP** — **CAPTCHA**. Капча подразумевает cookies; это явно в Privacy. N = **30/мин**, затем капча.
20. **DSA:** предпочтение — официальный публичный EU DSA / Discord Statement of Reasons, если есть стабильный публичный запрос. Если в v1 источника нет — **каркас** (пояснение + исходящие официальные ссылки), маршрут **зарезервирован**, пункт **скрыт из основной навигации** (и из пилюль hero), пока данные живые. Не рисовать фейковый «SECURE ACCOUNT». Не скрейпить с обходом капчи. Всегда есть **`/lookup/dsa/:id`**: что есть у нас + ссылка в официальный реестр; выдуманных нарушений нет.
21. **Документация бота:** Lookup упоминается в v1 и в **футере**, и в **`/docs`**.
22. **Easter eggs** about/credits **сохраняем** при унификации chrome.
23. **Кэш:** TTL **15 мин** user/bot, **10 мин** invite/server. Логи абьюза: **хеш IP + хеш запрошенного id**, хранение **48 ч**, не публично, не recent-searches.

## 5. Функции и честность API

Принцип: UI не обещает полей, которых нет в официальном публичном ответе. Не использовать user-only / undocumented profile endpoints «как discord.com». Не скрейпить клиент Discord. Не обходить капчи официальных порталов.

Отдельное приложение Lookup: минимальные интенты, **без** privileged intents, **без** обязанности быть на гильдиях. Нужен bot token, потому что `GET /users/{id}` для произвольного ID требует авторизации бота. Invite API для публичных инвайтов доступен и без членства.

Существующий `dashboard/backend/member_lookup.py` — поиск участника гильдии для панели. К публичному Lookup **не** относится и **не** должен вызываться из процесса бота Cheterin.

### 5.1. User lookup

**Вход:** Snowflake пользователя (17–20 цифр). Не username, не `name#0000`.

**Источник:** официальный `GET /users/{id}` с токеном приложения Lookup.

**Кэш:** TTL **15 минут**.

**Можно показывать, если пришло:** id, username, global_name, discriminator (legacy), avatar/banner, accent color, public flags → бейджи, bot/system, avatar decoration, collectibles/nameplate — **только если поле есть**, дата создания из snowflake, CDN.

**Не обещать:** email, телефон, гильдии, друзья, био/pronouns, онлайн, голос, connected accounts, платежи, IP. Nameplate не рисовать, если поля нет.

**Ошибки:** невалидный id; 404; 429 (наш или Discord); 5xx. Без утечки тела Discord.

### 5.2. Bot lookup

**Вход:** Snowflake приложения / пользователя-бота.

**Целевой v1:** полная карточка — User object **и** публичные метаданные application (описание, теги, флаги, install params, **scopes, permissions, intents**).

**Источники:** `GET /users/{id}` + публичный application endpoint (без user-token). Если endpoint **флапает** — retry и опора на кэш (15 мин). Деградация до карточки только User-объекта бота — **исключение**, когда Discord вернул пусто, не продукт-стратегия.

**Не обещать:** owner email, токен, список серверов, привилегированные интенты «как в Dev Portal», скрытые slash-команды.

### 5.3. Server lookup

**Вход:** invite-код или URL. **Не** Guild ID.

**Источник:** официальный Invite API.

**Кэш:** TTL **10 минут**.

**Можно показывать то, что отдаёт инвайт.** Честно: снимок **публичного инвайта**, не полный аудит. Протухший код — понятная ошибка.

**Не обещать:** участники, роли, каналы кроме invite-канала, бан-лист, lookup по guild id.

### 5.4. Permissions Calculator

**API Discord не нужен** для маски. Локальные Permission Flags.

UI: группы чекбоксов, decimal/hex, scopes, **generic** `discord.com/oauth2/authorize?...&permissions=…`, поле **Client ID**, **пресеты** Client ID приложения Lookup и бота Cheterin из конфига окружения (публичные ID приложений, не bot tokens). Live preview роли.

Связь: с карточки бота, если известен permissions integer — «открыть в калькуляторе».

### 5.5. Avatar & Banner Downloader

Не хостинг чужих файлов. Сборка URL CDN из hash.

**Скачивание:** основной путь — прямые ссылки `cdn.discordapp.com`. **Same-origin прокси** в `lookup-api` — fallback, когда браузер режет CORS или нужно контролируемое имя файла. Прокси не кэш-хостинг на диске и не публичная файломойка.

Типы: avatar/banner пользователя; icon/splash/banner гильдии — **только после успешного invite-lookup**.

### 5.6. Badges List

Справочник-сетка. На карточке — только флаги из API. Не угадывать Nitro, которого нет в User object.

### 5.7. Snowflake

Локально. Epoch Discord, UTC. Невалидный id — без запроса к Discord. Кнопки «открыть как User / Bot».

### 5.8. DSA

Отдельный режим, не Group DM. **Не** пункт основной нав и **не** пилюля hero, пока нет живого источника.

**Источник:** сначала официальная публичная прозрачность EU DSA / Discord Statement of Reasons, если стабильно запрашивается по id. Иначе страница-каркас: зачем раздел, что мы не выдумываем статусы, ссылки на официальные ресурсы.

**Шаринг:** URL вида `/lookup/dsa/:id` **всегда**. Если апстрим не умеет query по id: показываем, что есть у нас (часто — ничего кроме id) + outbound на реестр. **Запрещено** сочинять категории нарушений и «SECURE ACCOUNT» без данных.

На карточке user: блок DSA **только** при реальных данных.

### 5.9. Plugins

Каталог + внешние ссылки. Контент задаёт оператор (список при создании; правки в репо/манифесте). Нет формы «прислать плагин» для публики в v1.

Плагины **не** исполняются на `cheterin.online`.

### 5.10. Поиск, кэш, лимиты, логи

- Один сабмит — один канонический URL.
- Нет автодополнения по чужим запросам, нет счётчика «искали N раз».
- Кэш успешных ответов: **15 мин** user/bot, **10 мин** invite/server. Ключ = тип + id/код. Не витрина и не «база пользователей Cheterin».
- Рейт-лимит: **30 запросов в минуту с IP** → далее капча; до порога и при превышении Discord — **429** с понятным retry. Капча = cookies → Privacy.
- Антиабьюз-логи: **хеш IP + хеш queried id**, TTL **48 часов**, только оператор, не UI.

### 5.11. Что продукт сознательно не делает

См. §11. Кратко: нет Group DM, recent feed, DM Deleter, guild-id lookup, OAuth в Lookup, privileged intents, скрейпа, публичного API для третьих лиц, рекламы, смешивания с ValChecker.

## 7. Архитектура (high-level)

### 7.1. Как сейчас устроен Cheterin

- Корень: `main.py` + cogs, `locales/`, `assets/`.
- Панель: `dashboard/frontend` + `dashboard/backend` (aiohttp), старт из процесса бота.

Lookup **нельзя** вшить туда же.

### 7.2. Три процесса / три секрета

1. **Бот Cheterin** — текущий token, privileged intents, гильдии, панель.
2. **Lookup API** (`lookup-api/`) — token приложения Lookup, кэш, rate limit, капча, прокси Discord REST, fallback CDN-прокси, опционально DSA-источник.
3. **Lookup UI** (`lookup/`) — SPA на `/lookup/*`.

OAuth панели Lookup не использует.

### 7.3. Домен и маршрутизация

Один хост `cheterin.online`:

- `/lookup`, `/lookup/*` → Lookup UI;
- `/api/lookup/*` → Lookup API;
- `/about`, `/docs`, `/credits`, `/terms`, `/privacy`, `/cookies`, `/disclaimer` → как сейчас панель (legal — общие страницы);
- остальное → бот+панель.

`/about` **остаётся** в `dashboard/frontend`. Lookup SPA **не** забирает витрину бота.

### 7.4. Данные

- Нет БД пользователей Lookup в v1.
- Кэш: память/короткий KV; TTL 15 мин (user/bot), 10 мин (invite/server).
- Антиабьюз: хеш IP + хеш id, 48 ч, не публично.
- Плагины: статический манифест, правки оператора.
- Капча: состояние на IP; cookies провайдера — в Privacy.

### 7.5. Связь с `/about` и docs

About не вызывает Discord и не содержит поиска. Кнопка «Lookup» = навигация. `/docs` в v1 содержит упоминание Lookup. Никакого bot token в браузере.

### 7.6. Наблюдаемость

Health Lookup API **внутренний** (оператор). Не блок на hero. Алерты 401 и всплеск 429. Дискретный публичный статус — не v1.

## 8. Ре-организация файлов и папок

**Зафиксировано: вариант A.** Пока нет задачи реализации — файлы не создавать и не двигать. Этот раздел больше не «идеи на выбор».

### 8.1. Почему не внутри панели

Lookup — отдельный продукт: другой процесс, другой токен, другой бандл. Складывать в `dashboard/frontend` — раздуть панель, смешать CSS, привязать деплой к боту.

### 8.2. Вариант A (принят): `lookup/` + `lookup-api/` на корне

На одном уровне с `dashboard/`:

- `lookup/` — SPA: `/lookup/*`, chrome, словари Lookup, **копия CSS-токенов** кита.
- `lookup-api/` — HTTP: users, invites, application RPC, кэш, лимиты, капча, health, CDN-прокси fallback. **Не** импортирует cogs, `dashboard.backend.app`, `member_lookup.py`, ValChecker.

Публичный chrome панели (`/about`, legal, docs): те же значения переменных, restyle `--landing-*` как второй темы нет. Мост: кнопка на `/about`, ссылки в футере и `/docs`.

Варианты B (страницы внутри панели) и C (`dashboard/lookup-frontend`) **отклонены** для публичного v1.

### 8.3. `/about` не переезжает в Lookup SPA в v1

Оставить в `dashboard/frontend`. Не импортировать lookup-компоненты в `DashboardShell`. Lookup-классы поиска/карточек не попадают в `index.css` панели.

`packages/ui` в первой итерации **не** создаём.

### 8.4. Что не складывать в дерево Lookup

- Токен бота Cheterin.
- `locales/` слэш-команд.
- VALORANT assets.
- Тесты панели и cogs.
- `graphify-out/`.

Корень бота (`main.py`, плоские модули) **этим планом не рефакторится**.

### 8.5. Прокси и сборка

- Lookup UI — отдельный артефакт, `base` = `/lookup/`.
- API env: `LOOKUP_DISCORD_TOKEN` и публичные Client ID для пресетов калькулятора — не `DISCORD_TOKEN` бота.
- Прокси `/api/lookup` на том же хосте.

## 9. Фазы

Каждая фаза — поставка без скрытого рефакторинга бота.

Полная карточка (scopes/permissions/intents). Retry + кэш 15 мин. Не сдавать «только User» как готовый v1.

Только invite, кэш 10 мин, карточка инвайта.

Snowflake, Permissions **полный** (URL + Client ID + пресеты конфига + live preview), Badges.

**Фаза 5 — Avatar & Banner**

Попытка официального публичного источника. Маршруты `/lookup/dsa` и `/lookup/dsa/:id` всегда. Если источника нет — каркас + ссылки, **скрыть из нав и hero**. Не блокирует 1–5. Не фейковая таблица.

**Фаза 7 — Plugins**  
Страница каталога. Контент — список оператора (может прийти в момент создания). Без публичных сабмишенов.

**Фаза 8 — `/about`, docs, chrome**  
Restyle `/about`, docs, credits, футер → кит. Кнопка Lookup. **Без** поиска на about. Упоминание Lookup в **`/docs` и футере**. Easter eggs **оставить**. Убрать `--landing-*` как вторую тему.

**Фаза 9 — Legal**  
Один комплект: обновить Terms/Privacy; добавить `/cookies` и `/disclaimer`; секции Lookup, отдельное приложение, кэш, хеш-логи 48 ч, капча, CDN, отсутствие recent. Оператор Cheterin Group Ø / Nandak070. Футер Lookup → те же URL.

**Фаза 10 — Жёсткость**  
Капча после 30/мин с IP; 429 с retry до капчи; мониторинг токена; мобильный hero; a11y поля; проверка изоляции от бота; чеклист §6.4 и §2.10. Health не на hero.

## 12. Зафиксированные ответы

Бывшие открытые вопросы. Сняты. Полный смысл — в §2 и связанных разделах.

1. **`/about` и `/lookup/about`.** About бота остаётся в `dashboard/frontend`: restyle + кнопка Lookup, без поиска. Lookup SPA — `/lookup/*`. **`/lookup/about` в v1 есть** (короткий about продукта, не копия бота, без гигантского hero). Поиск — на `/lookup`.
2. **Префикс API.** Тот же хост: `/api/lookup/...`. Без lookup-поддомена.
3. **Имя в шапке.** **Cheterin** (не «Cheterin Lookup»).
4. **Язык.** Общий **`chetbot_ui_lang`**.
5. **DSA.** Официальный публичный EU DSA / Discord SoR, если стабильный query есть. Иначе каркас + официальные ссылки, **скрыть из основной нав**, маршрут оставить. Без фейка и без скрейпа капчи.
6. **Кэш и логи.** TTL **15 мин** user/bot, **10 мин** invite/server. Абьюз: **хеш IP + хеш id**, **48 ч**, не публично, не recent feed.
7. **Application RPC.** Со scopes/intents (полная карточка). Retry/кэш; деградация только если Discord пуст. Не user-only как цель v1.
8. **Cookies.** Одна legal-страница Cookies на оба проекта. Lookup **не** cookieless-only: язык через **`chetbot_ui_lang`** (cookie/`localStorage` как у остального Cheterin). Капча позже добавляет свои cookies — в той же странице и Privacy.
9. **Plugins.** Список от оператора при создании; реализатор вносит. Модерация только операторская. Без публичных сабмишенов в v1.
10. **Калькулятор прав.** Полный: generic invite URL **и** поле Client ID **и** пресеты Lookup + Cheterin из конфига (не секреты в коде).
11. **Ассеты.** Оба: прямой CDN основной, same-origin прокси — fallback.
12. **Мониторинг.** Не на hero. Внутренний health — да. Без фейковых дашбордов. Дискретный футер — не v1.
13. **Legal / оператор.** Cheterin Group Ø / Nandak070. Terms / Privacy / Cookies / Disclaimer — **один** набор. Канон: `/terms` `/privacy` `/cookies` `/disclaimer` на `cheterin.online`; футер Lookup туда же.
14. **Рейт-лимит UX.** До порога — **429 + retry**. После **30 запросов/мин с IP** — **CAPTCHA**. Капча = cookies → Privacy.
15. **Sharable DSA URL.** Всегда `/lookup/dsa/:id`. Нет query у апстрима — наши факты (возможно пусто) + ссылка в официальный реестр. Без выдуманных нарушений.
16. **Docs.** Lookup в v1 в **футере и `/docs`**.
17. **Easter eggs.** Сохранить при унификации chrome.
18. **Папки.** Вариант A: `lookup/` + `lookup-api/` на корне. B и C отклонены.
19. **Токены кита.** Да, дубль CSS-переменных в `lookup/` и публичном CSS дашборда до появления `packages/ui`.

Ранее зафиксированное (приглашение для сервера, нет Group DM, нет публичных recent, отдельный token, уголь+тёмно-красный, паритет макетов, сильный копирайт) остаётся в силе — см. §2.1.
