## Контекст и разбиение на фазы

Полный проект — веб-панель управления ботом (Vite+React), покрывающая весь функционал
бота: feedback/CTD-панели, модерация тикетов, конструктор кнопок/ролей, конструктор
эмбедов/сообщений (в духе discohook.app), полное управление событиями и голосованиями,
lockdown, бан/кик, инфо об участниках, выдача ролей (в т.ч. массовая), редактор конфига.
Это слишком большой объём для одного спека, поэтому проект разбит на фазы:

1. **Фаза 1 (этот документ) — Фундамент**: встроенный веб-сервер, Discord OAuth2, React-каркас.
2. Фаза 2 — Модерация участников (бан/кик, инфо, роли, массовая выдача, lockdown).
3. Фаза 3 — Конструктор контента (эмбеды/сообщения от бота, конструктор кнопок/форм).
4. Фаза 4 — Feedback/CTD (создание панелей, модерация активных тикетов/жалоб).
5. Фаза 5 — События и голосования (полный жизненный цикл).
6. Фаза 6 — Редактор конфига (`.env` кроме токена).
7. Фаза 7 — Деплой на Oracle (tmux) и привязка домена `cheterin.online`.

Каждая фаза — отдельный спек → план → реализация. Ниже — дизайн только Фазы 1.

## Архитектура

**Один процесс, один asyncio event loop.** `main.py` вместо `bot.run(token)` переходит на
`asyncio.run(main())`, где `main()` через `asyncio.gather()` параллельно запускает:
- `bot.start(token)` — как сейчас;
- aiohttp `AppRunner`/`TCPSite` на `DASHBOARD_PORT` — новый веб-сервер.

Веб-сервер получает прямую ссылку на объект `bot` и работает с его живым кэшем
(участники, роли, каналы) — без дублирования состояния и без IPC/отдельного процесса.

**Если веб-часть падает при старте** (например, порт занят, не заданы обязательные
переменные окружения) — это логируется как ошибка, но **бот всё равно запускается и
работает** без дашборда. Обратное (веб уронил бота) недопустимо.

## Auth-флоу (Discord OAuth2)

1. Фронтенд: кнопка "Войти через Discord" → редирект на `/api/auth/login`.
2. Бэкенд генерирует `state` (CSRF-защита, короткоживущая cookie) → редирект на Discord
   `authorize` со scope `identify` (без `guilds.members.read` — роли берутся из кэша
   самого бота, а не из OAuth-scope).
3. Discord редиректит на `/api/auth/discord/callback?code=...&state=...`. Путь коллбэка
   намеренно отличается от уже используемого на боевом Discord-приложении
   `https://chetmedia.com/auth/callback` (другой Client ID, но во избежание путаницы при
   переезде на боевого бота/домен `cheterin.online` используется свой явный путь).
4. Бэкенд проверяет `state`, меняет `code` на access token, получает Discord-профиль
   (`id`, `username`, `avatar`) через Discord API.
5. Бэкенд ищёт участника в гильдии через кэш бота: `guild.get_member(user_id)`, при
   промахе — фолбэк `guild.fetch_member(user_id)`.
6. Проверка доступа: участник должен иметь одну из ролей `DASHBOARD_ACCESS_ROLE_IDS`
   **или** `guild_permissions.administrator == True`. Нет доступа → страница "Доступ
   запрещён", сессия не создаётся. Есть доступ → создаётся сессия, редирект на дашборд.

## Сессии и права доступа

- Сессия — `aiohttp-session` с `EncryptedCookieStorage` (ключ `SESSION_SECRET` из `.env`).
  Хранит только `discord_user_id`. **Роли/права не кэшируются в сессии** — перепроверяются
  на сервере из живого кэша бота при каждом запросе к защищённым эндпоинтам, чтобы разжалование
  роли отражалось немедленно, а не после истечения сессии.
- `GET /api/auth/me` — текущий юзер (id, username, avatar, уровень доступа) для фронтенда.
- `POST /api/auth/logout` — чистит cookie.
- На dev (`http://localhost`) cookie выставляется с `Secure=false`; переключение на
  `Secure=true` — через переменную окружения при переходе на HTTPS/домен (вне этой фазы).

## Новые переменные `.env`

```
DASHBOARD_PORT=8080
DISCORD_CLIENT_ID=...
DISCORD_CLIENT_SECRET=...
DISCORD_OAUTH_REDIRECT_URI=http://localhost:8080/api/auth/discord/callback
SESSION_SECRET=<случайный сгенерированный ключ>
DASHBOARD_ACCESS_ROLE_IDS=1324239354209632357,1324239354209632358,1505359848433516734
```
(Kapo, Moderator, CTD — плюс отдельная проверка `guild_permissions.administrator`,
не завязанная на список ID.)

уже получены от пользователя и будут прописаны в `.env` рабочей копии на этапе реализации
(не хранятся в этом документе и не выводятся повторно в чат).

## Обработка ошибок

- **Старт сервера:** отсутствие/невалидность `DISCORD_CLIENT_ID/SECRET`, `SESSION_SECRET`,
  `DASHBOARD_PORT`, либо занятый порт → дашборд не поднимается, ошибка в лог, бот работает
  без дашборда.
- **OAuth callback:** пользователь отклонил доступ / Discord вернул `error` → редирект на
  логин с "Вход отменён". Несовпадение `state` или невалидный/просроченный `code` → `400`,
  редирект на логин с "Ошибка авторизации, попробуйте снова".
- **Участник не найден** (`get_member`/`fetch_member` оба вернули `None`) → "Доступ
  запрещён" (не участник сервера).
- **Роли не подходят** → "Доступ запрещён", сессия не создаётся.
- **Защищённые API-запросы:** нет/просрочена сессия → `401 JSON`, фронтенд редиректит на
  логин. Сессия валидна, но текущие роли не проходят проверку (разжаловали) → `403 JSON`,
  фронтенд чистит локальный auth-стейт, показывает "Доступ запрещён".
- **Кэш бота временно недоступен** (например, сразу после рестарта) и фолбэк
  `fetch_member` тоже упал (рейт-лимит/сеть) → `503` "Не удалось проверить доступ,
  попробуйте позже" — не блокируем намертво и не пускаем по умолчанию.
- **Фронтенд:** глобальный error boundary + toast-уведомления на сетевые сбои API.

## Проверка (manual verification)

Автотесты для полного OAuth-флоу нецелесообразны на этой фазе (требуют живого Discord).
Проверка вручную:
1. `python main.py` — тестовый бот стартует, лог показывает, что aiohttp поднялся на `DASHBOARD_PORT`.
2. Убить процесс на `DASHBOARD_PORT` заранее — убедиться, что бот всё равно стартует
   (веб-часть падает без остановки бота).
3. `npm run dev` во фронтенде, открыть в браузере — видно страницу логина.
4. Пройти OAuth2 через тестовый Discord-аккаунт с одной из разрешённых ролей — попасть на
   каркас дашборда, `/api/auth/me` отдаёт корректные данные.
5. Тем же аккаунтом, но без разрешённых ролей/прав — увидеть "Доступ запрещён".
6. Разлогиниться — cookie очищена, повторный заход на защищённую страницу редиректит на логин.
